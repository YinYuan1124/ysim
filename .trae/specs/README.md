# SpecKit 规范（.trae/specs）

> 本目录为 AFSIM 二次开发的功能规格库。每个功能（或批次）一个文件夹，命名 = **序号 + 功能**（如 `i18n-batch18` = 第 18 号 i18n 功能批次）。

## 目录结构规范

```
.trae/specs/
├── README.md              # 本规范
├── roadmap.md             # 二开总体规划（双主线四方向、扩展点分层、实施路线、避坑）
├── ext-01-data-export/    # 数据出口（Observer/中间件/落盘）— P0
├── ext-02-protocol-gateway/  # 外部接入（DIS/HLA/XIO/数实联动/推演后端）— P1
├── ext-03-model-toolchain/   # 模型与想定工具链（模型库/行为智能/编辑器）— P2
├── ext-04-eval-platform/     # 评估与工程化（指标/VV&A/并行/国产化）— P3
├── i18n-batch18/          # 界面本地化（已完成，补充归档）
│   └── msgid-batch18/     # 历史/子批次归档（消息 ID 化第十八批）
```

## 三件套职责

| 文件 | 内容要点 | 完成时机 |
|---|---|---|
| `spec.md` | 背景目标 / 决策完备明细（通道、清单、范式、红线）/ 不译边界 / 验证标准 | 实现前编写；**实现完成后补充归档** |
| `plan.md` | 分阶段推进计划（基础→主干→深水区→扫尾）+ 后续批次注意事项 | 与 spec 同步 |
| `tasks.md` | 可勾选任务清单 + 验收标准（含命令与口径） | 逐项执行并勾选 |

## 编写要求

1. **决策完备**：spec 必须能让不读代码的人按表执行（文件、行号、ID/通道、原文一字不动）
2. **踩坑入册**：历史教训（键/显示分离、死条目、BOM、协议键）以范式形式写入 spec，供后续批次沿用
3. **口径一致**：spec/plan/tasks 三处累计口径（条目数、finished 数）必须与 SKILL.md、project_memory.md、doc 修改日志一致
4. **状态标注**：实现已完成的工作，spec 头部标注"实现已完成，本文为补充归档"；规划中的工作标注"计划态（未实施）"
5. **存档独立**：历史批次内容移入子目录归档，不删除（如 msgid-batch18）
