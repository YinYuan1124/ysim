## 第十三批：端到端联调示例（e2e_visual_demo）+ WS 握手 Accept 缺陷修复

**需求**：提供 mission 后台仿真驱动浏览器可视化的端到端联调示例。

**交付**：tests/e2e_visual_demo/（situation.html 自包含态势页 + e2e_ws_verify.py 无头验证 + 600s 演示想定 + README）。

**缺陷（联调过程中发现并修复）**：ysim_data_export WS 握手 `Sec-WebSocket-Accept` 计算错误——自研 Python 客户端未校验 Accept 而漏检，浏览器/标准客户端（严格校验 RFC 6455）全部拒绝握手。

**根因**（YsimDataExport.cpp Sha1 输出循环）：`for (int j = 31; j >= 0; j -= 8) out += char((h[i] >> j) & 0xFF);` —— 移位窗口与 &0xFF 组合错位：j=31 只取最高 1 位、j=23 取 bit23-30…… 正确为 **j=24/16/8/0**。错误值呈 5 组 [01/00+3字节] 特征（(h>>31)&0xFF 恒为最高位 0/1）。

**调试链**（用时较长，方法论值得记录）：
1. 浏览器/.NET 严格客户端握手失败 + Python 裸客户端成功 → 定位服务端 Accept 值错误
2. 摘要 hex 模式分析（5 组 0x01 前缀）排除随机性 → 判定系统性窗口错位类 bug
3. Python 翻译 C++ 实现竟正确 → 翻译时无意识修正了输出段（>>24/16/8/0），误导排查方向
4. VS2022(v141 工具集) 独立编译 1:1 抄写版复现错误 → 排除环境/编译器因素
5. 80/160 轮逐轮 trace 对拍全同 + FINAL h 数组正确 → 锁定输出段
6. Python 复算 buggy j 循环精确复现观测错误值 → 根因闭环

**修复验证**：①严格 Accept 校验 MATCH（RFC 标准向量）；②无头 e2e_ws_verify.py 6/6 PASS（握手/快照 4 平台/状态流 52 帧/心跳/零解析失败/字段齐全）；③.NET ClientWebSocket（浏览器同等严格度）握手 Open + 10s 收 171 帧（state 165/added 4/heartbeat 2）。
