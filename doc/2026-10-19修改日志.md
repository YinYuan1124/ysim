### 一、源码侦察结论（用户方案 vs AFSIM 2.9 真实机制）

| 用户方案 | AFSIM 2.9 实际 | 落地方式 |
|---|---|---|
| `Mission.exe xx.txt --param speed:500` | mission 命令行仅 `-rt/-fs/-es/-fio/-sm/-mi/-list-variables/-help`，无 `--param` | 插件经 `WsfApplicationExtension::ProcessCommandLine` 注册自有选项 `--ysim-port <n>`；想定参数化走原生预处理变量 |
| SDL 中 `require_plugin` 挂载 | 全源码无该命令；插件由 `WsfPluginManager` 构造期自动扫描 exe 相对目录加载 | DLL 部署 `mission_plugins/`（`swdev_plugin_install`），启动即挂载 |
| 继承 `WsfProcessor` 在 `FrameComplete` 推流 | `WsfProcessor` 须挂到具体平台才被 Update（全局导出须改每个平台，违背零侵入） | 改用 `ApplicationExtension → ScenarioExtension → SimulationExtension` 扩展链 + `WsfObserver::AdvanceTime` 帧回调（每帧触发，等价 FrameComplete） |

### 三、插件功能

- **扩展链**：ApplicationExtension（`--ysim-port` 命令行，优先于想定）→ ScenarioExtension（`ysim_data_export { port/heartbeat_interval/deadband/min_update_interval } end_ysim_data_export` 想定配置块）→ SimulationExtension（生命周期管理）
- **事件订阅**（WsfObserver，只读零侵入）：PlatformAdded / PlatformDeleted / MoverUpdated（state 帧核心数据源）/ AdvanceTime（帧驱动心跳）
- **消息协议**：JSON 行协议（UTF-8，`\n` 分隔），六种帧：sim_start / platform_added / platform_removed / state / heartbeat / sim_complete；state 含 time/id/name/platform_type/side/lat/lon/alt_m/speed_mps/heading_deg/pitch_deg/roll_deg（WGS84，弧度→度在 IO 边界）
- **线程模型**（性能红线）：仿真回调只做"取数→拼 JSON→入队"（队列上限 10000 丢最旧）；独立 TCP 线程 accept 多客户端 + 广播（SO_SNDTIMEO 200ms + TCP_NODELAY，断线剔除，best-effort 不阻塞仿真）
- **增量推送**：降采样（同一平台两次推送最小间隔）+ 位置死区（位移小于阈值跳过）

## ext-01 阶段 B：统一消息中间件（适配器抽象 + WebSocket/UDP 多通道）

> 工作包：`.trae/specs/ext-01-data-export/`（阶段 B，spec §8）
> 变更范围：仅重构 `YsimDataExport.cpp` 单文件（工程文件零改动）

### 一、架构升级

- **Channel 适配器抽象基类**：统一"仿真线程入队 → 独立网络线程消费广播"骨架；派生类只实现 Run()；消息层（JSON 行）与通道层完全解耦
- **TcpChannel**：阶段 A 逻辑重构为适配器形态 + 新增快照补推
- **WebSocketChannel**：最小 RFC 6455 服务端**零第三方依赖自实现**（内置 SHA-1/Base64；HTTP Upgrade 握手；FIN+opcode1 文本帧 7/16/64 位长度编码；ping→pong 应答；close 帧断开；上行数据帧一律忽略——单向推送语义）

- **新客户端快照补推**：SimulationExtension 维护"元信息帧 + 最近状态帧"双缓存（互斥锁保护），新 TCP/WS 客户端接入即收全量态势再入实时流

### 二、配置与命令行扩展

- 想定块新关键字：`tcp_port`（`port` 保留别名）/ `websocket_port` / `udp_address` / `udp_port` / `udp_ttl`；端口 0 = 禁用通道；默认三通道全开（31600 / 31601 / 239.16.16.16:31602）
- 命令行新增 `--ysim-ws-port <n>` / `--ysim-udp-port <n>`（与 `--ysim-port` 同语义，须置于文件名之前）

### 三、代码质量改进

- 帧构造器全部改用 snprintf 单模板（BuildSimpleFrame/BuildPlatformAdded/BuildPlatformRemoved/BuildStateFrame），**根除阶段 A 的 JSON 拼接丢引号问题类别**（本批零拼装错误）

## ext-01 阶段 C：结构化落盘（CSV 时序 + SQLite 快照 + 评估指标表）

> 工作包：`.trae/specs/ext-01-data-export/`（阶段 C，spec §9）
> 变更范围：YsimDataExport.cpp（Recorder 实现 + 配置/命令行）+ CMakeLists.txt（SQLite 链接）

### 一、选型结论（源码侦察）

- **CSV 而非 Parquet**：依赖树（build/3rd_party）无 Arrow/Parquet，引外部依赖成本高；CSV（UTF-8 with BOM）Excel/pandas 双友好
- **SQLite 静态库**：3rd_party 自带 sqlite-3.32.3-x64-vs2017（1.5MB lib 无 DLL），静态链入插件零部署问题；`swdev_package_*` 宏的 sqlite 变量仅 wizard 子树作用域可见（宏会静默跳过），插件 CMakeLists 按 `${CMAKE_BINARY_DIR}/3rd_party/sqlite-3.*` 解压约定直接定位
- **指标分级落地**：交战类指标（命中率/发现时间/杀伤链）依赖 Track/Engagement 数据源（§8.8 遗留），本批先落地平台级聚合指标

### 二、Recorder 架构（与 Channel 平行的持久化 Sink）

- 独立类（非 Channel 派生）：持久化语义与网络广播不同；线程模型沿用性能红线——仿真回调只填 POD 记录入队（上限 10000 丢最旧）→ 独立落盘线程批量消费
- **单队列保序**：平铺超集 Record（kind + 15 标量 + 4 字符串），kind ∈ {state, event, metric}，落盘线程按 kind 分流写表
- **CSV**：RFC 4180 转义 + 每批 fflush（崩溃不丢已写数据）；**SQLite**：`journal_mode=OFF; synchronous=OFF`（分析导出吞吐优先），每批事务 + prepared 语句
- **快照表**：platforms 表收尾写入元信息 + 最终状态（断点恢复数据源），removed_time=-1 表示仍在场
- **失败降级**：目录/文件/库打开失败仅告警并禁用对应 Sink，仿真照常

### 三、输出文件布局（每轮运行独立时间戳子目录，蒙特卡洛多轮天然隔离）

```
<record_directory>/run_YYYYMMDD_HHMMSS_mmm/

```

- 命令行：`--ysim-record <dir>`（启用并指定输出根目录，优先于想定，须置于文件名之前）

## ext-01 阶段 D：验收 + 适配器热切换（ext-01 收官）

> 工作包：`.trae/specs/ext-01-data-export/`（阶段 D，spec §10）
> 变更范围：YsimDataExport.cpp（ControlChannel + 读写锁并发模型 + Complete 停机优化）

### 一、适配器热切换实现

- **ControlChannel 控制通道**（独立类）：`control_port` 想定关键字 / `--ysim-control-port` 命令行（默认 0=禁用）；单客户端串行命令循环（select 20ms 节拍），命令集 `add_tcp <port>` / `add_ws <port>` / `add_udp <addr> <port> [ttl]` / `remove <port>` / `list` / `help`（空格分隔 token，不引 JSON 解析器；响应为 JSON 行与数据流格式统一）
- **并发模型**：`mChannels` 由 `std::shared_timed_mutex`（C++14）保护——仿真线程 Publish 持 shared_lock 只读遍历、控制线程增删持 unique_lock；**停机在锁外**（remove 锁内摘链后锁外 FlushAndStop，避免持锁 sleep 阻塞仿真帧）；新增通道注入同一快照 provider（TCP/WS 热通道新客户端同样快照补推）
- **端口冲突预检**：同端口已在列表即拒绝；控制端口自身不可 remove

### 二、验收结论（四项全 PASS，spec §10.4）

| 验收项 | 结果 | 明细 |
|---|---|---|
| 官方示例全流程数据可见 | ✅ | 40s -rt 长跑：31600 全生命周期流（sim_start→added×4→state→removed×4→sim_complete）解析零失败；落盘 states=648 与推流完全一致、指标 25 条 |
| 适配器热切换 | ✅ | 13/13 断言：list/add_udp/remove/add_tcp/remove 全链路；TCP 热通道新客户端收快照补推（4×platform_added）+实时流；UDP 热通道入组收实时流（组播无连接语义无快照属预期）；remove 后双通道停流；主通道全程不断流 |
| 帧率下降 < 5% | ✅ | **-rt 实时口径：基线 60.261s vs 全开 60.508s = +0.41%**；全速口径归因：600s 想定 +11%（空帧回调 0.44μs×60 万帧 + 100ms 固定尾部）、60s 想定 +80%（基线墙钟仅 0.28s，属采集成本非帧率损失） |

### 三、验证期发现并修复的问题

1. **Complete 串行停机尾延迟**（帧率基准暴露）：原逐通道 FlushAndStop（各含 150ms sleep）→ 600s 全速 +24% 墙钟；改为**单次 100ms 排空 + 并行 Stop**，收敛至 +11%（全速口径）/+0.41%（实时口径）
2. **帧率基准口径修正**：事件驱动全速模式的墙钟增量是"采集成本"（数据没白采）；帧率红线的工程度量应为 **-rt 实时模式仿真是否跟上实时节拍**——实测 +0.41% 达标
3. 热切换脚本首轮 13/14：唯一 FAIL 为断言口径错误——UDP 组播无连接语义（无接入事件），快照补推仅适用 TCP/WS；脚本断言修正后 13/13（机制本身经 TCP 热通道验证正常）
4. 修复 Complete 后全量回归重跑（热切换 13/13 + 落盘 648=648）无回归

### 6.3 关键教训

1. **`PakSerializeImpl.hpp` 必须显式包含**：XIO 各头文件仅含 `PakSerializeFwd.hpp` 前置声明，自定义 Packet 用 `aBuff& f1& f2` 序列化操作符时缺实体定义头会 LNK2019（MSVC 对仅声明无定义的 inline 模板外链到库内实例化符号，插件侧不可见）——WSF 自有 .cpp 使用点全部显式含 Impl 头是范式信号
2. **`pause_for_connection true` + 客户端 cRESUME 是全量事件可见的必要条件**：全速 mission 在 XIO 握手完成前已推进数百秒（实测客户端握手时仿真已到 t=539），早期事件全部丢失；mission 等待期间帧循环空转但心跳仍按墙钟发送，不会死锁
3. **心跳命令需带时间单位**：`heartbeat_interval 1.0 s`（cTIME 类型），裸数字报 "must be followed by s"
4. **多播接口前缀须匹配本机网卡**：demo 样例的 `10.` 在本机（192.168.x）无效，客户端与 mission 块都要按实际网段填
5. **原生 AuxData 推送（Packet ID 73）是外部客户端噪声**：未注册该包的客户端每帧刷 "Received unknown packet"，验证配置用 `send_aux_data_updates false` 关闭
6. **WsfSimulationExtension 无参构造**：基类不接受 string（与 Application/ScenarioExtension 不同），默认构造即可；跨子树独立工程链构建树库时，各库 `*_export.h` 生成头位置分散（build/{util,wsf}/source、build/{genio,packetio,dis,geodata,tracking_filters,util_script} 根），须逐一补 include 路径

### 8.3 关键教训

3. **单航点航路会瞬移**：RouteMover 以航路首点为起始锚，单航点=直接跳到目标；须双航点（首点=当前位置 GetLocationLLA、首点速度 WsfPath::cUSE_PREVIOUS）
4. **set_route/set_speed 类型域是 RouteMover 族**（WsfAirMover→WsfWaypointMover→WsfRouteMover）：brawler 想定（WSF_BRAWLER_MOVER）dynamic_cast 恒空——验证想定须切 air_movers 版且保留 2v2.txt 全局 script_variables（FileIO 对象被平台脚本运行期引用）
5. **位移断言区间须按机动窗口物理口径设定**：45s 想定中 pause 占 5s，靶标实际机动窗口仅 8s（5 m/s² 加速度→百米级位移），首轮按目标距离设的公里级区间假失败；断言前先算"可用机动时间 × 加速能力"的物理上界
6. 编译错误输出被 `Select-Object -Last 3` 截断致根因（cRAD 不存在）两轮未定位——排查常量名直接 grep 头文件（UtMath.hpp）比对，勿依赖截断日志

### 10.4 关键教训

1. **Fire PDU 的 fireMissionIndex 是 DisUint32（4B）**——非直觉的 2B：Fire PDU 总长 96B，weaponType@64/warhead@72/fuse@74（按 2B 推导偏移全错 2B）
2. **Emission 系统记录偏移以抓包实测为准**：源码 Put 链推导 name@33，实测 name@32/function@34/number@35——错位指纹是读值 [0xA1,0x05] 恰为表值 36001 低字节+5 的相邻排列；PDU 解析偏移须冒烟校准，源码推导只能做初值
3. **发包前钩子是字段补齐的正路**：比补发 PutPdu 干净（不重复发包，改的就是原生包）；Signal/Transmitter 的 MessageTransmitted 内部构造 PDU 无观察者——两 PDU 缺口只能记录（Signal 载荷补齐归 B3 私有 PDU 域）
4. **同 DLL 双扩展驻留模式**：WsfPluginVersion/WsfPluginSetup 导出入口唯一，第二功能模块经普通 Register_* 函数由主入口调用，扩展名独立（ysim_dis_field_patch）——DLL 演进不破坏既有扩展
5. **钩子连接时机 Initialize 足矣**：Fire/Detonation/Emission 均为运行期事件（vs B1 映射注入必须赶在平台创建前 AddedToSimulation）；Initialize 连接 + 依赖序保发现链就绪
6. **Signal PDU 的最小触发构造**：WSF_COMM_TRANSCEIVER + WSF_COMM_MEDIUM_GUIDED medium + execute at_time 脚本 SendMessage（test_medium_script_method.txt 范式）——guided medium 与距离无关，双平台 comm 即可触发 MessageTransmitted → Signal PDU
7. **SA-10C 交战想定单进程闭环 60s**：warfare 想定结构（types.txt 武器链 include + 派生类型挂 comm）F-18 30000ft 500kts 从 20.4km 航线接近，WSF_TASK_PROCESSOR 20km 自动交战——RT 60s 内 Fire×2/Detonation×2/Emission×14/Signal×3 全触发

### 11.3 关键教训

1. **首轮 CMake 分支缺陷**：OFF 选项只挂在"未命中"分支——3rd_party 包在场时 OFF 仍会链接（STATUS 显示 "sqlite linked" 暴露）；三态选项的"无条件跳过"必须是**独立首分支**（if OFF → 跳过一切查找），否则语义被查找结果短路
2. **Edit 剥 BOM 再犯**（本批 YsimDataExport.cpp 中招）：症状链 C4819 警告 → C1020 意外 #endif（中文注释被 GBK 代码页错位解析后吞掉 #ifndef 行）——含中文 C++ 每轮 Edit 后必须字节级复查 BOM
3. **构建树源目录是 `src/` 非仓库根**：CMAKE_HOME_DIRECTORY=E:/afsim/ysim/src，`cmake -S` 传错目录 configure 直接失败但旧缓存仍可 build（误导性：build 输出的是旧配置产物）——改缓存变量前先查 CMakeCache.txt 的 CMAKE_HOME_DIRECTORY
4. **降级冒烟须换新输出目录**：旧 record_directory 含历史 ysim_export.db 会污染"无 .db 生成"判定，冒烟想定按轮次隔离输出目录
5. CMakeLists.txt 无 BOM 含中文注释是安全的（CMake 按 UTF-8 读脚本，不受 MSVC 代码页影响）——BOM 红线只约束 C++ 源文件
